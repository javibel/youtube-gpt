# Operator configuration service

The service validates every task in every profile, checks required runtime contract/adapter versions and rechecks credential availability before activation. Dependencies must come from trusted server composition; actor identity never comes from a request body. Credential checks report availability only and must not execute a paid provider probe.

Preview performs no writes. Its opaque token binds the operator, candidate, expected current revision, reason and expiration. Activation uses the store’s compare-and-swap operation; rollback previews an existing immutable revision. New exceptions record the authenticated actor. Lost activation acknowledgements can be retried without creating another switch. In-memory previews expire after at most five minutes; process restart requires a new preview.

This module is not an installed administrative endpoint or a live runtime bootstrap. Its tests use synthetic providers and credentials. PostgreSQL integration uses only the isolated test schema and role-bound stores. Network timeouts and runtime discovery must be provided by trusted composition.

The web now has a protected administrative POST route for validate, preview, rollback preview and activate. Server composition still must install the stores and declarations; an absent runtime returns 503. Same-origin JSON requests and the existing administrator session are required. The runtime derives a stable actor hash from that authenticated session and rechecks authorization for service operations. No local server has been started.

GET and POST now share a 30-second monotonic deadline across authorization, streamed body and service waiting. HTTP abort retires the waiter even if a dependency ignores cancellation; a stalled body cancellation cannot extend the deadline. Late authorization/body completion cannot begin a service call. The original service may still finish after its HTTP waiter retires: an activation already invoked returns an unconfirmed/uncertain 503, never a cancellation or success claim. The route does not resend, generate or renew a preview token. An explicit state read and retry with the original unexpired operator-bound preview use the existing service checks and compare-and-swap; reconstructed JSON, expired tokens and fresh service instances confer no authority.

The administrative browser panel also has a total 30-second wait across fetch and JSON, including state reads and preview/activation commands. Retirement ignores late callbacks, isolates sessions by user/email/authentication and coalesces rapid commands and Strict Mode's initial GET. A newer explicit read retires the preceding read while preserving the last confirmed configuration. Reading state keeps the original preview and its server-issued expiry. Activation without a matching positive acknowledgement retains uncertainty; a successful explicit state read only observes the current revision and permits an explicit retry of the same original, unexpired preview. It does not cancel the original request or manufacture authority. Expiry removes the activation control while retaining uncertainty and state consultation; it does not create a replacement preview. A confirmed acknowledgement survives failure of the independent subsequent read.

Directed React/session/HTTP/clocks are synthetic. Native test-schema integration observes the original database switch, withheld service or browser JSON acknowledgement, explicit state read and same-token retry with one audit event. A consumed/expired preview and a new service instance cannot regain activation authority from the observed revision. Tests do not establish operational authentication, browser durability, remote cancellation or acceptance.
