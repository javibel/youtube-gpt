Infra Optimizer

Health monitoring + correlacion de patrones — diario 02:45
Descripcion
Configuracion
Que hace

Recopila metricas de infraestructura (gratis) y Claude Opus correlaciona patrones de degradacion para detectar problemas antes de que afecten a los usuarios.

  • Tendencia response time de Sentinel (7 dias)
  • Conexiones DB activas (pg_stat_activity)
  • Espacio en disco (PowerShell)
  • PM2 restart count y memory por proceso
  • Error rate de los logs (errores/hora)
  • Presencia de reports de otros agentes
Anomalias que detecta
  • Response time >3s
  • DB connections >75% del pool
  • Disco >80% (warning) o >90% (critico)
  • Memory >200MB por proceso
  • Restarts inesperados
  • Error rate >20/dia
  • Agentes que no generaron reporte
Fixes permitidos
  • alert — Email con diagnostico
  • clean_disk — Borrar reports >7d, rotar logs
  • restart_service — PM2 restart (strict allowlist)
  • adjust_schedule — Proponer cambio de horario cron (solo propuesta)
Conexiones
←Sentinel memory + PM2 + Neon + LogsRecibe de
Lee response times de Sentinel, conexiones de BD, espacio en disco, PM2 info y error rates de los logs. Todo gratis, sin llamadas API.
→Claude AI (Opus)Envia a
Claude correlaciona: "Response times suben a las 3am cuando corren guardian+social-optimizer simultaneamente".
→PM2 + FilesystemActua sobre
Puede limpiar disco (reports viejos, logs) y reiniciar servicios PM2 especificos.

Meta-Optimizer

El cerebro del sistema — analiza y mejora TODOS los agentes — domingos 03:30
Descripcion
Configuracion
Que hace

Lee la efectividad de TODOS los fixes de TODOS los agentes, analiza patrones y propone mejoras al sistema completo. Es el unico agente que puede modificar otros agentes.

Fase 1: Recoleccion (gratis)
  • auto-fixes.json — historial completo de fixes y efectividad
  • agent-memory/*.json — issues persistentes de cada agente
  • reports/ — reportes de la ultima semana
  • agent-config.json — config actual
Fase 2: Auto-tune (gratis, sin IA)
  • Fixes con >80% exito → cooldown -20% (reaccionar mas rapido)
  • Fixes con <30% exito → cooldown +50% (dejar de gastar recursos)
  • Re-enable fixes desactivados si el issue no aparece en 14+ dias
  • Max 3 cambios por ejecucion
Fase 3: Claude Opus (1 llamada)
  • Claude analiza TODO el sistema: que funciona, que no, por que
  • Puede proponer: ajuste de cooldowns, re-enable, nuevos fixes
  • Nuevos fixes van a proposed-fixes.json (requieren aprobacion humana)
Seguridad
  • Kill switch: meta-optimizer.enabled en agent-config.json
  • Max 3 cambios de config por ejecucion
  • Bounds hardcodeados (no puede poner mentionRate > 0.50, etc.)
  • Audit trail completo
  • Rollback automatico si un cambio empeora metricas
Kill switch global — desactivar para pausar auto-mejora
Conexiones
←Todos los agentes (reports + fixes + memory)Recibe de
Lee datos de efectividad de auto-fixes.json, memorias de cada agente, y reportes de la semana. Tiene una vista panoramica de todo el sistema.
→Claude AI (Opus)Envia a
Claude Opus 4.6 analiza la efectividad de todo el sistema y propone mejoras: "El fix X tiene 80% exito pero el fix Y solo 40% — el prompt del social-optimizer necesita mas contexto".
→agent-config.json + auto-fixes.jsonModifica
Puede ajustar cooldowns, re-enable fixes desactivados, y proponer nuevos fixes (estos ultimos requieren aprobacion humana).
→Resend (Email)Envia a
Envia propuestas de nuevos fixes y analisis semanal al owner para revision y aprobacion.

Feature Monitor

Health checks de 24 endpoints + auto-heal con Claude — 2x/dia 07:00 y 19:00
Descripcion
Configuracion
Que hace

Testea 24 endpoints de la plataforma en 5 categorias: infraestructura, features publicas, rutas AI/Claude, rutas YouTube-auth, y extension. Cuando detecta fallos, intenta auto-curar antes de escalar al humano.

Flujo de auto-heal
  • 1. Escanea 24 endpoints (HTTP status + response time)
  • 2. Si hay fallos, espera 30s y re-confirma (descarta transitorios)
  • 3. Claude Opus diagnostica el patron de fallos y recomienda accion
  • 4. Ejecuta fix (redeploy Vercel, restart PM2, etc.)
  • 5. Espera 60s y re-verifica endpoints
  • 6. Solo escala a humano si todos los auto-fixes fallan
Fixes permitidos
  • claude-feature-diagnosis — Claude analiza y recomienda: redeploy, check keys, retry, alert
  • restart-local-services — Reinicia PM2 tunnel si hay fallo de conectividad local
  • redeploy — Trigger Vercel deploy hook automaticamente
Categorias de endpoints
  • Infraestructura: Landing, API Health, Login, Blog, Sitemap
  • Features publicas: Trending, Extension SEO Quick
  • AI/Claude: rutas que usan Anthropic API
  • YouTube-auth: rutas que requieren YouTube auth
  • Extension: endpoints del Chrome extension
Conexiones
←ytubviral.com (24 endpoints)Testea
Hace HTTP requests a 24 endpoints de la plataforma para verificar que estan operativos y responden en tiempo.
→Claude AI (Opus)Diagnostico
Si hay fallos confirmados, Claude analiza el patron y recomienda la accion de fix mas probable.
→Vercel Deploy Hook + PM2Actua sobre
Puede triggear un redeploy en Vercel via deploy hook o reiniciar servicios PM2 locales.
→Resend (Email)Escalacion
Solo envia email al owner cuando TODOS los auto-fixes han fallado. El humano es el ultimo recurso.

Outreach Pipeline

Sistema automatizado de adquisicion de usuarios: discover → email → DM → comment → follow-up → monitor
Descripcion
Flujo
Canales
Pipeline completo

Sistema de 6 etapas que funciona 24/7 para encontrar creadores de YouTube, contactarlos por multiples canales y convertirlos en usuarios de YTubViral.

  • Discover (outreach-discover.js) — 6x/dia. Busca canales de YouTube via API (500-25K subs), extrae email publico, calcula SEO Score del ultimo video. ~60 contactos nuevos/dia.
  • Email Send (outreach-send.js) — 6x/dia. Envia emails personalizados via Resend con analisis SEO value-upfront (HTML + score card + tips). Hasta 60 emails/dia.
  • Reddit DM (outreach-reddit-dm.js) — 3x/dia. Escanea 18 subreddits de YouTube, detecta creadores compartiendo sus videos, envia DM personalizado ofreciendo analisis SEO gratis. ~15 DMs/dia.
  • Reddit Targeted (outreach-reddit-targeted.js) — 2x/dia. Encuentra posts donde creadores piden ayuda/feedback SEO, comenta con consejos utiles + mencion sutil a YTubViral usando personas Alex y Ferran. ~16 comments/dia.
  • Follow-up (outreach-followup.js) — 2x/dia. Reenvia email a contactos que no respondieron despues de 3 dias.
  • Monitor (outreach-monitor.js) — cada 3h. Revisa replies en Reddit posts y tweets donde publicamos.
  • Community Posts (outreach-post.js) — 1x/dia. Publica posts de beta testers en subreddits relevantes.

Volumen total: ~150+ interacciones/dia distribuidas en email, Reddit DMs, Reddit comments y community posts.
